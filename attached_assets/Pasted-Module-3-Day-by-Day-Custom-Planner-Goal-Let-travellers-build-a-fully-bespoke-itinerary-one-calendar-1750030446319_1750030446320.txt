Module 3: Day-by-Day Custom Planner
Goal	Let travellers build a fully bespoke itinerary one calendar day at a time, combining any mix of transfers, single-day tours, guides, or add-ons, while keeping pricing independent from package logic used in the other modules.

1. User-Experience Flow
Date Range Selection

Calendar (month grid) where the user drags / clicks to pick holiday start → end.

Selected range populates a vertical timeline (left column = dates, right column = “Add Service” buttons).

Per-Day Service Builder

Pressing “Add Service” opens a modal with three tabs:

Transfers – point-to-point, time + vehicle selector, supports one-way or return.

Tours / Activities – filtered by city, duration, language, difficulty.

Guides-Only & Extras – hire guide by hours, add entrance-ticket bundles, meals, etc.

Each chosen item appears as a card under its date with time, passengers, price, and a ● drag handle to reorder.

Real-Time Price Sidebar

Shows running totals:

Sub-totals per day

Module-level total

Cross-module cart total (if user also has items from Modules 1 & 2).

Conflict & Capacity Checks

Instant warnings for overlapping times, unavailable guides, or vehicle capacity overflow.

Checkout

User can pay a deposit or full amount.

Generates single Booking ID even if services span multiple cities.

2. Technical Specification (hand-off for Replit)
2.1 Tech Stack
Layer	Recommendation
Front-end	React + Vite (already supported on Replit) with Tailwind CSS. Use react-day-picker for the calendar and @tanstack/react-query for data-fetch.
Back-end (API)	Node 18 + Fastify (lightweight vs. Express, great on Replit free tier).
DB	PostgreSQL (Replit DB or external Supabase); Prisma ORM for type-safe models.
Auth	Re-use existing JWT/session strategy from Modules 1 & 2.
Pricing Engine	Isolated service (pricing.ts) to keep formulas in one place.

Why separate booking_days? Keeps one-day granularity, lets you run SELECT queries like “show me all services on 2025-07-12” easily.

2.3 Key API End-points (REST)
Verb	Path	Description
GET	/services?type=&city=	Fetch catalogue items for Service Picker.
POST	/bookings	Create empty booking, returns booking_id.
POST	/bookings/:id/days	Add date (creates booking_day row).
POST	/days/:day_id/services	Add service card; payload {service_id, passengers, time, meta}.
PATCH	/services/:booking_service_id	Update quantities, times, etc.
DELETE	/services/:booking_service_id	Remove card.
GET	/pricing/quote?booking_id=	Returns full price breakdown (see § 2.4).
POST	/checkout	Locks availability, creates Stripe session.

All endpoints return idempotency keys to allow safe retries from the client.

2.4 Pricing Logic
txt
Copy
Edit
If service.pricing_mode = 'per_group':
    price = base_price
Else if 'per_person':
    price = base_price * passengers

# Day-level Discount (optional business rule):
If count(services_in_same_day) >= 3:
    apply 5% day-bundle discount

# Multi-day Discount (optional):
If booking length >= 7 days and total_amount >= 1000 USD:
    apply 3% global discount

# Taxes / surcharges
- Tourism police road permit (if transfer distance > 150 km): flat 250 EGP per transfer.
- High-season supplement (date ∈ peak list): +10% to eligible tours.
Store discounts as separate rows in booking_adjustments for auditability.

2.5 Business Rules & Validation
Check	Details
Time overlap	start_time < other.end_time AND end_time > other.start_time within same day & passengers.
Vehicle capacity	passengers ≤ max_capacity(vehicle_cat).
Guide availability	unique constraint (guide_id, date) in guides_schedule table.
Origin ≠ destination	for transfers, except “within-city” flag.
Cut-off	no new bookings < 12 h before start_time.

Use Replit Deployments (always-on) for the Fastify server; static React front-end served via Vite preview or separate deployment.

Add prisma migrate deploy in the Replit “Run” command so migrations run automatically on start.

Opt-in to Replit Nix environment for deterministic builds (replit.nix).
