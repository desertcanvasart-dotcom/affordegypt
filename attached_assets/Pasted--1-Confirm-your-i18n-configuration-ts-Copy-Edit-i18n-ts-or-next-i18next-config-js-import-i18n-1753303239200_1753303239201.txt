
1 — Confirm your i18n configuration
ts
Copy
Edit
// i18n.ts (or next-i18next.config.js)
import i18n from 'i18next';
import { initReactI18next } from 'react-i18next';

i18n
  .use(initReactI18next)
  .init({
    lng          : 'en',           // current language
    fallbackLng  : 'en',           // ALWAYS keep a fallback
    ns           : ['common','blog'], // namespaces you actually use
    defaultNS    : 'common',
    keySeparator : '.',            // false  ⇢  “blog.sinaiGuide.title” is ONE key
                                   // '.'     ⇢  path-style lookup blog → sinaiGuide → title
    debug        : process.env.NODE_ENV === 'development',
  });
If you want nested JSON keep keySeparator: '.' (the default).
Translation file:

json
Copy
Edit
// public/locales/en/blog.json
{
  "sinaiGuide": {
    "title":       "Sinai Travel Guide",
    "subtitle":    "Coral Reefs, Desert Peaks & Bedouin Culture",
    "description": "Everything you need to plan the perfect Sinai trip.",
    ...
  }
}
Component usage:

tsx
Copy
Edit
const { t } = useTranslation('blog');
<h1>{t('sinaiGuide.title')}</h1>
If you prefer “flat” keys set keySeparator: false.

json
Copy
Edit
{
  "blog.sinaiGuide.title": "Sinai Travel Guide",
  ...
}
Component usage stays the same (t('blog.sinaiGuide.title')).

2 — Load the namespace on every page that needs it
Next.js + next-i18next
tsx
Copy
Edit
export const getStaticProps: GetStaticProps = async ({ locale }) => ({
  props: {
    ...(await serverSideTranslations(locale ?? 'en', ['common', 'blog'])),
  },
});
Plain React / CRA
Make sure the component (or a top-level wrapper) calls:

tsx
Copy
Edit
const { t } = useTranslation(['common','blog']);
3 — Find the missing keys quickly
While debug: true is enabled you’ll see console warnings:

cpp
Copy
Edit
i18next::translator: missingKey en blog blog.sinaiGuide.title blog.sinaiGuide.title
Paste that list straight into the relevant JSON file(s) and write the actual text.

4 — Batch-generate a starter file (optional)
If you have hundreds of keys, run:

bash
Copy
Edit
npx i18next-scanner "src/**/*.{js,jsx,ts,tsx}" \
  -o public/locales/en/blog.json \
  --keySeparator="." --replace
It will create a JSON containing all keys it can find with the value set to the key itself—handy for translators.

5 — Checklist
✅ public/locales/<lng>/<namespace>.json exists and contains the keys.

✅ ns array in i18n.init() or serverSideTranslations includes "blog".

✅ useTranslation('blog') (or useTranslation(['blog','common'])) wraps the component.

✅ keySeparator matches your JSON style (nested vs flat).

✅ fallbackLng: 'en' ensures English never breaks even if other languages are incomplete.
